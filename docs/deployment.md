# Windows 部署与运维

支持 Windows 10/11、Windows Server 2016 及以上 x64，本机磁盘、单应用实例、SQLite。EXE 包含模板、完整前端资源（含下划线前缀共享模块）、SVN 工具及许可证，无需另装 Node.js 或 Go。实际环境验证范围见[验收与限制](acceptance.md)。

## 首次安装与端口

生产构建交付 `SVNova-<7位提交号>.exe` 及同名 `.exe.sha256` 文件，文件名中的提交号与页脚版本一致。以下命令使用固定部署文件名 `SVNova.exe`；可将交付文件重命名为此名称后替换，沿用原工作目录和服务路径。

将 EXE 放在固定程序目录，运行账号须有工作目录和仓库目录读写权限。以控制台方式启动：

```powershell
.\SVNova.exe --work-path D:\SVNova\work
```

默认访问 `http://127.0.0.1:3000`。若需内网首次安装：

```powershell
.\SVNova.exe --work-path D:\SVNova\work --install-listen 0.0.0.0:3001
```

安装页的访问地址填写浏览器实际使用的地址，例如 `http://192.168.1.10:3001`；`0.0.0.0` 是监听地址，不能作为浏览器访问地址。设置管理员、数据库和仓库目录后，配置写入 `custom/conf/app.ini`。

`--install-listen` 仅供未配置实例使用。安装完成后再次启动只需原 `--work-path`，监听与访问地址以 INI 为准；误用新工作路径会打开另一套实例，不会自动找到旧数据。相同工作目录不能同时启动控制台和服务。

## 工作目录与配置

默认工作根为 EXE 所在目录；建议始终显式指定固定绝对路径。默认布局：

```text
work/
  custom/conf/app.ini
  data/svnova.db
  data/secret.key
  data/repositories/<组织名>/<仓库名>/
  data/tools/
  log/svnova.log
  instance.lock
```

数据库、仓库、密钥均不在 EXE 内。工具按固定包摘要释放，并在启动时核验，修改已释放工具会阻止启动。配置字段：

| INI 节 | 字段 | 含义 |
| ---- | ---- | ---- |
| server | APP_DATA_PATH | 应用数据路径，默认 data |
| server | HTTP_ADDR、HTTP_PORT | 安装后的监听地址与端口，默认 127.0.0.1、3000 |
| server | ROOT_URL | 浏览器使用的完整访问地址，用于同源校验和消息链接 |
| database | DB_TYPE、PATH | 仅 sqlite3，默认 data/svnova.db |
| repository | ROOT | 受管仓库根目录，默认 data/repositories |
| repository | MIRROR_CONVERSION_TIMEOUT | 快速转换整体超时，默认 24h，正 Go duration，例如 48h；重启生效 |
| security | INSTALL_LOCK、SECRET_KEY_URI | 安装锁及原加密密钥的绝对本机 file URI |
| log | MODE、ROOT_PATH | 安装时写入的日志信息；当前实现固定追加至工作根 log/svnova.log，不支持切换模式或目录 |

相对存储路径以工作根解析，不能假定修改 APP_DATA_PATH 会自动搬迁数据库、仓库或工具。迁移路径须保留实际配置引用的数据及原密钥。旧 `config.json` 在读取时转换为 INI并保留原存储路径和密钥，原 JSON 留存备查。

更改端口时停止程序，在现有 INI 中同时修改 HTTP_ADDR／HTTP_PORT 和匹配的 ROOT_URL，再启动；无需重复安装。通过 HTTPS 反向代理访问时使用 HTTPS 的 ROOT_URL，以启用 Secure Cookie；代理保留原站点地址及状态轮询路径，不缓存认证 JSON。

## Windows 服务

停止控制台实例，以管理员身份在 EXE 所在目录运行：

```powershell
.\SVNova.exe --work-path D:\SVNova\work service install
.\SVNova.exe --work-path D:\SVNova\work service start
Get-Service SVNova
Get-CimInstance Win32_Service -Filter "Name='SVNova'" |
    Select-Object Name, State, StartMode, PathName
```

服务名 `SVNova`，自动启动，默认 LocalSystem。注册保存当前 EXE 和工作目录的绝对路径。若改成专用账号，须授予完整工作目录及外部存储路径权限；不使用 Windows 集成身份认证远端 SVN。映射网络盘不作为本机磁盘使用。

排队／运行中任务在停止与重启时的处理，以及 SVN、LDAP、通知的恢复差异，见[任务调度专题](task-scheduling.md#2-启动停止与运行器)。

```powershell
.\SVNova.exe --work-path D:\SVNova\work service stop
Get-Service SVNova
# 确认 Stopped 后才能替换 EXE 或卸载
.\SVNova.exe --work-path D:\SVNova\work service uninstall
```

卸载只删除服务注册，不删除工作目录。已注册且 EXE 路径不变时，升级不用重新 install；如更换程序／工作路径，先停止并卸载旧注册，再从正确位置注册。

## 升级、回退与数据保护

1. 在任务记录确认当前操作，安排停机。正常停止服务或控制台，等待进程退出。
2. 备份 INI、SQLite（包括尚未合并的 WAL）、原密钥和全部仓库／外部存储目录。工作目录包含敏感数据，应限制 ACL。
3. 只替换固定路径的 EXE，仍传入原工作路径启动；检查日志、登录、版本、仓库和任务记录。

当前数据库 schema 为 **14**，启动执行模型补列和迁移，拒绝高于支持版本的库；不能用旧 EXE 直接打开升级后的数据库。回退需使用对应停机数据库快照及同一密钥，仓库副本也须与快照匹配。schema14 删除旧通知仓库排除列，不更改通知开关／凭据，不补发取消历史。

安装后密钥缺失会拒绝启动，不可用新密钥替换。应用不提供数据库快照或归档备份产品功能，宿主机备份由管理员负责。

## 迁移与同步操作

本地源必须是服务器可访问且停止写入的 SVN 仓库。迁入会移动源，同盘重命名，跨盘 hotcopy 后校验再清理源。verify 和跨盘 hotcopy 默认每条命令 24 小时，并非整个迁移的总时限；普通 SVN 命令默认 30 分钟。关闭服务会取消命令，重启按持久阶段恢复普通任务。

若提示 staging／目标目录已存在或发布后源清理失败，应核对任务、目录及有效副本，不覆盖现有目录、不删除唯一副本。断电与磁盘满仍属于未完成的真实故障验收。

SVN 服务密码加密保存且不写日志；svn 通过标准输入接收密码，但上游 svnsync 通过进程参数接收源密码，应限制服务器本地进程查询权限。

远端镜像要求 HTTP/HTTPS 完整仓库根地址和完整历史读取权限；支持加密保存凭据及显式跳过 TLS 验证，默认验证。UUID 变化或远端修订回退会停止同步，保留本地内容。默认同步 8 小时，最小 10 分钟，0 禁用自动同步。历史修订属性核对可能较慢，阶段进度以实际命令输出为准。仓库操作全局串行，其他仓库的设置保存也可能因互斥返回冲突。

快速转换仅面向 ready、本地、完整性正常的仓库，管理员或 Owners 操作。必须确认同源、历史未独立修改、远端完整读取权限且本地不再接受外部写入。只检查身份／r0／钩子和镜像配置，不逐修订 dump 比对或新增全库 verify；不能证明历史完全一致。活动提交／修订属性钩子或旧镜像元数据冲突会拒绝，不能直接覆盖用户钩子。

转换提交后台任务后可关闭页面。整体超时从实际执行开始计时，默认 24 小时，不含排队；失败恢复原配置和 r0／受控钩子，保留数据。重启先恢复日志，再将中断转换标为需手动重试。恢复失败时保留日志与全部副本，程序可能拒绝启动；不要手工删除恢复日志或改 Kind 绕过检查。

## LDAP 与钉钉配置

LDAP 支持多配置单启用、LDAPS／StartTLS；默认验证证书、分页 500、同步开启、成功空结果保护。稳定身份 AD 通常用 objectGUID，LDAP 通常用 entryUUID。过滤器支持 `%s`／`%[1]s`，邮箱属性可用 mail。修改或切换源前查看清理预览，准备 Owners 继任者，确认后相关 LDAP 用户及会话／成员关系会删除，历史保留。

全站 LDAP 调度使用北京时间五字段 cron，例如 `30 2 * * *` 为每天 02:30，默认 `0 0 * * *`。旧 HH:MM 不兼容，需重新保存；锁忙等待、停机不补跑，停用／切换源或修改调度会取消未开始旧任务，不触发用户清理。缺少下一次执行时间的表达式不触发。

钉钉通知配置全站单个官方 HTTPS 加签机器人，Webhook／Secret 加密且不回显。默认总开关关闭，保存不发送；测试消息须主动操作，自动测试不向真实群发消息。无按仓库排除功能，仅失败记录可以手动重发。网络临时错误有限重试，超时和重启可能重复送达；默认投递保留 90 天，可选 30／180 天或永久。

## 日志与排障

运行日志为 `log/svnova.log`，主要记录启动和错误；业务阶段和结果查看仓库任务记录、LDAP 同步历史及钉钉投递记录。页脚显示构建提交前 7 位，无构建元数据则显示开发版，运行不需要 Git。生产 EXE 使用 `scripts/build.ps1` 构建；开始构建和打包前均要求 Git 工作区及暂存区干净且无未跟踪文件（忽略文件除外），否则报错，先提交再重新构建。

| 现象 | 检查 |
| ---- | ---- |
| 请求验证失败 | 浏览器访问地址、ROOT_URL、代理和 Cookie 的协议／主机／端口是否一致 |
| 提示已有实例或目录不可访问 | 控制台／服务是否同时运行、工作目录和账户权限 |
| 无法连接远端 SVN | 明确错误代码、服务账号凭据、证书、网络和完整读取权限；E170013 本身不足以定位唯一原因 |
| 转换恢复失败 | 保留库、恢复日志和原密钥，核查日志及外部钩子变化后恢复，不手工清库 |
| 仓库大小待统计 | ready 仓库在空闲时补算；失败至少 5 分钟后再试，页面不实时扫描 |

浏览和单文件下载受 16 MiB 命令输出上限限制，超过上限失败而不返回截断内容；目录树／日志的 XML 输出也有界。修订历史每页 10 条，前端仓库列表及首页活动每页 10 条。业务时间统一北京时间，原始 SVN API 日期保留原格式。

## LDAP 单配置升级

当前版本只保存一份 LDAP 配置，管理入口为 `/-/admin/ldap`。旧版数据库仅在 LDAP 配置、LDAP 用户和同步历史全部为空时支持升级，保留本地账号、组织、仓库和任务。若检测到旧 LDAP 数据，程序拒绝升级并保持原数据；应继续使用原版本处理，不要手工删除数据或修改 schema 版本。升级前按既有流程停机并保留完整工作目录；开发验证使用新的独立工作目录。旧多源页面和 API 不再可用。
